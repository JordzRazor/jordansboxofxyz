SNIPER

relay 127.0.0.1:7355 relay not checked

Ship text out of a designated web page into a local staging area, so code written in a browser chat lands in the right file on disk without a copy-paste round trip.

chat.deepseek.com (your tab, already logged in)
   |
   |  userscript: "→ Claude" button on every code block   (Alt+S = selection)
   v
GM_xmlhttpRequest --POST--> 127.0.0.1:7355/drop   (+ X-Sniper-Key)
   |
   v
relay.py --> drops\<ts>-<n>-<slug>.txt    raw text, ready to place
             drops\<ts>-<n>-<slug>.json   metadata: url, lang, target, mode
             drops\manifest.jsonl        append-only log

No credential is ever handled. The relay does not authenticate to DeepSeek and never touches their API — the browser you are already logged into does the reading, and forwards only the text you point at.

Setup

  1. Get the relay running

    The relay is the local half, and is not distributed from this page — it lives in your sniper folder. It can install itself to start at login:

    cd %USERPROFILE%\sniper .\install-autostart.ps1 <- or just .\run.ps1 to start it once

    Autostart uses two mechanisms because they fail differently: a Startup-folder shortcut (minimized — that window is the live log) plus a scheduled task at logon +1 min as the fallback. Running both is safe; the relay is single-instance and stands down if one is already serving.

  2. Install the userscript

    Requires Tampermonkey. Clicking this opens its install screen:

    Install sniper.user.js

    Or, from a copy on disk: Tampermonkey dashboard → Utilities → Import from file.

  3. Paste your relay key

    The copy served here ships with a placeholder where the key goes. Read yours:

    type %USERPROFILE%\sniper\.sniper_key

    Then in the Tampermonkey editor, replace the placeholder on the const KEY line:

    const KEY = '__PASTE_YOUR_SNIPER_KEY__';
    Why this step is manual. Your working copy of the script carries the key inline, and that key is the whole of the relay's authentication. Published verbatim at a public URL it would be readable by anyone — and while the relay is loopback-bound so nobody reaches it remotely, any page you visited could then POST valid drops into your drops\ folder. So this page never carries the key, and the build refuses to ship if it finds one.

  4. Chrome only: allow user scripts

    chrome://extensions → Tampermonkey → Details → enable Allow User Scripts. Without it, Manifest V3 Chrome silently runs nothing — no error, no script, no clue.

  5. Reload and confirm

    Reload the DeepSeek tab. The page console should log:

    [sniper] armed on deepseek

    Every code block gets a → Claude button, and a ⧉ pill appears bottom-left for environments and the review console.

Is the relay up?

GET 127.0.0.1:7355/health

This runs in your browser, so it only ever sees your machine's relay. Nothing is sent anywhere.

If this fails but the relay is running: Chrome gates requests from a public site to a loopback address behind its Private Network Access preflight, which the relay does not answer yet. That blocks this button, not the userscript — the userscript uses GM_xmlhttpRequest, which runs in the extension context and is not subject to it. Open http://127.0.0.1:7355/health directly for the authoritative answer.

Addressing a drop

The first line of a block may carry its own coordinates. It is stripped from the .txt, so the sidecar is ready to place verbatim.

// >> mcmod\pack\data\foo.mcfunction @replace <the actual content>
PartAccepts
leader// # -- ; % <!-- /* — or none
mode@replace (default) @new @append @patch @note
noteanything after the mode is kept as free text

No directive is fine — the drop is staged unaddressed, for a human to route in the review console at 127.0.0.1:7355/console.

Arming another site

The script is armed per-site. Add an @match line to its header and reload the page:

// @match https://chat.deepseek.com/* // @match https://your-other-site.example/*
sniper — the relay stays on your machine. This page carries the userscript and these instructions, nothing else.
