狙撃 · sniper

Code written in a chat tab, landing in the right file on disk.

A button on every code block in a browser chat. One click ships it to a relay on your own machine, which stages it for review before anything touches a file — no copy-paste, no credentials handled, nothing leaving loopback.

relay 127.0.0.1:7355 userscript 0.33.0 relay not checked 
chat.deepseek.com / chat.qwen.ai   (your tab, already logged in)
   |
   |  userscript: "→ Claude" on every code block   (Alt+S = selection)
   v
GM_xmlhttpRequest --POST--> 127.0.0.1:7355/drop   (+ X-Sniper-Key)
   |
   +--> code        --> drops\          staged, waiting for you to apply it
   +--> whole page  --> envs\<name>\    deployed live, and written to the ledger
   +--> prose       --> context\        read for intent, never placed as a file
   |
   v
snipes.jsonl   every snipe, and what became of it

No credential is ever handled. The relay does not authenticate to DeepSeek or Qwen and never touches their API — the browser you are already logged into does the reading, and forwards only the text you point at.

支度Setup

  1. Get the relay running

    The relay is the local half, and is not distributed from this page — it lives in your sniper folder. Either double-click Sniper Relay on the desktop, or:

    cd %USERPROFILE%\sniper .\tray.ps1 <- background, tray icon, restarts itself on a code change .\run.ps1 <- a visible window instead, if you want to watch the log

    In tray mode there is no console window, so the output goes to runs\relay-<stamp>.log and the tray menu opens it. It also watches relay.py and restarts the moment its bytes change, so a background process cannot quietly go stale.

    To start it at login instead: .\install-autostart.ps1. No elevation is needed at any point — there is no UAC prompt anywhere in this setup.

  2. Install the userscript — from your relay, not from here

    Requires Tampermonkey. With the relay running:

    .\install.ps1

    That starts the relay and opens http://127.0.0.1:7355/sniper.user.js?key=<your key>, and Tampermonkey offers to install it. This is the path worth taking, for two reasons that are not obvious:

    Your key is already in it, so there is no placeholder to edit — and the relay injects @updateURL and @downloadURL pointing back at itself, so every future version is one click. A copy installed any other way has neither: it works, and then silently never updates again.
    No relay yet? Take the copy served from this page instead

    Install sniper.user.js (0.33.0)

    This copy ships with a placeholder where the key goes, because this page must never carry your key. Read yours and paste it into the const KEY line in the Tampermonkey editor:

    type %USERPROFILE%\sniper\.sniper_key const KEY = '__PASTE_YOUR_SNIPER_KEY__';
    It will not auto-update. A script installed from this page has no update channel wired to your machine, so you will be hand-installing every version. Once your relay is up, install from it once and that problem goes away permanently.

  3. Chrome only: allow user scripts

    chrome://extensions → Tampermonkey → Details → enable Allow User Scripts. Without it, Manifest V3 Chrome silently runs nothing — no error, no script, no clue.

  4. Reload and confirm

    Reload the chat tab. A toast names the version it is running, and the page console logs it too. Every code block gets a → Claude button, and a ⧉ pill appears bottom-left carrying the name of the environment this chat is pointed at.

点検Is the relay up?

GET 127.0.0.1:7355/health

This runs in your browser, so it only ever sees your machine's relay. Nothing is sent anywhere.

If this fails but the relay is running: Chrome gates requests from a public site to a loopback address behind its Private Network Access preflight, which the relay does not answer yet. That blocks this button, not the userscript — the userscript uses GM_xmlhttpRequest, which runs in the extension context and is not subject to it. Open http://127.0.0.1:7355/health directly for the authoritative answer.

虚実When a code block is not text

Qwen does not render code as markup. It mounts a Monaco editor per block — the editor VS Code is built on — and Monaco is a virtual list: only the lines the viewport can show exist in the page at all, and their elements are recycled as you scroll.

That single fact explains every symptom that looks like a broken scrape: reads that come back shuffled, a line-number gutter counting 27,28,29,24,25,26, and a 200-line file arriving as 29 lines that open <html> and never close it. No amount of reading the screen recovers a line that was never mounted. It does not exist.

So the capture asks the editor instead — its own model where the page exposes one, otherwise mounting the whole document and pairing every rendered line with its gutter number. Because each line arrives numbered, “this is the whole file” becomes a count that can be proved rather than hoped for, and a partial capture is refused with the exact lines it is missing.

If a site still will not give its text up: the review console has a paste box. Copy the block by hand, paste it there, and it is staged exactly like anything sniped — same guards, same ledger.

帳場The console is the panel

Everything is reviewed at 127.0.0.1:7355/console, the first entry in the ⧉ menu. It is a front end over the same command-line tool that does the placing, so containment, backups and the ledger are identical whichever way you drive it.

It showsWhy it is there
recent snipeswhere each one went: queued, deployed, identical, duplicate, context, refused
out of phasethe tab running an older script than the relay serves, or a file holding bytes the queue never put there
refusalsthe verbatim capture, the reason, and the counts behind it — kept, not discarded
clearmoves a stage into cleared\; nothing is deleted

Prose may go straight in. Code lands in pending, or it lands in completed — every byte that reaches a file is recorded with a sha before and after and a backup path, so the panel can always account for what is on disk.

宛先Addressing a drop

The first line of a block may carry its own coordinates. It is stripped from the .txt, so the sidecar is ready to place verbatim.

// >> mcmod\pack\data\foo.mcfunction @replace <the actual content>
PartAccepts
leader// # -- ; % <!-- /* — or none
mode@replace (default) @new @append @patch @note
noteanything after the mode is kept as free text

No directive is fine — the drop is staged unaddressed, for a human to route in the review console. A complete HTML document with no directive is the exception: it is deployed straight into the environment this chat is pointed at, and written to the ledger as it goes.

増設Arming another site

Two halves. The @match lines live in the script header, because a browser needs those at install time:

// @match https://chat.deepseek.com/* // @match https://chat.qwen.ai/*

Everything else — which selectors find a code block, a message, the composer, and what to exclude — lives in sites.json, which the script fetches from your relay at startup. Tuning a selector is a file edit and a tab reload, not a re-install.

"chat.qwen.ai": { "code": ["pre", "[class*=\"code-block\"]"], "messages": [".chat-response-message"], "exclude": [".monaco-editor"] }

Open the site and press Alt+D: the census reports which selectors hit, the most common classes on text-bearing nodes, and — if the page uses Monaco — the editor's own numbers.
